NexusRun bundles a model, its prompts, its config and its hardware preferences into a standard OCI artifact — then runs it on the fastest accelerator the host can actually use. No container runtime, no Python environment, no daemon. One static binary, about 3 MB.

Build it
git clone https://github.com/verdictlayer/nexusrun

Then make build. Needs Go 1.26+. Produces static, CGO-free binaries for 8 targets across Linux, macOS, Windows and FreeBSD.

Usable devices: GPU, CPU — and the GPU only through Ollama. Run a unit on llama.cpp and it goes to the CPU, because that build has no CUDA in it. Two backends, two different answers, reported separately instead of averaged into one optimistic number.

The idea

Detecting a GPU is not the same as being able to use it.

The machine above has a healthy Quadro RTX 5000. The driver works. nvidia-smi reports it happily. And llama.cpp still cannot touch it, because that build was compiled without CUDA.

Most tools check whether a device exists and schedule onto it. When the backend can't actually drive it, they fall back to the CPU without saying so — and every benchmark and capability claim quietly becomes a lie. NexusRun schedules on the intersection of what the machine has and what the installed runtimes can genuinely execute on, and tells you when those two disagree.

Reuses models you already have

A unit references a model instead of embedding it. Already pulled it with Ollama? NexusRun runs that exact blob from Ollama's store — no second download, no second copy on disk.

A typical unit is under 1 KB, because it's metadata, not weights.

Sealed units for air-gapped machines

When you need self-containment, --seal embeds the weights as OCI layers and export writes one file you can carry on a USB stick.

Verified: imported to an empty store and generated with no network and no Ollama.

Any registry, no special support

Units are ordinary OCI artifacts, so they push and pull from ghcr.io, Docker Hub, ECR, Harbor or a local zot — with their auth, signing and retention already solved.

Tested against a stock registry:2 with zero server-side changes.

Where it fits

A layer above the inference engine, not a replacement for one.

NexusRun delegates generation to llama.cpp or Ollama. What it adds is packaging, distribution, and honest hardware scheduling.

Status

What works, and what doesn't.

Never silently fall back is the project's one hard rule. It applies to this page too — so here is the unedited ledger.

Verified end to end on Linux
  • +Build, run and share — packaging, the OCI store, and export/import round trips
  • +Push and pull against a stock registry:2, needing no server-side support
  • +Ollama model reuse — runs weights Ollama already downloaded, no copy
  • +Air-gapped execution from sealed weights, with no network and no Ollama
  • +Warm-model daemon, plus a read-only web console for units, hardware and run history
  • +Kernel-enforced sandboxing — script units confined by Landlock to what they declare
Not done, and not pretended otherwise
  • –NPU execution. Detection and scheduling exist; the ONNX Runtime backend returns a clear error rather than quietly using the CPU
  • –GPU execution is implemented but unverified — the development machine's llama.cpp has no CUDA compiled in, so nothing has ever generated on it
  • –Sandboxing is Linux-only. On macOS and Windows, script units refuse to run without --no-sandbox
  • –Tools and MCP. The manifest accepts a tools: list that nothing consumes yet
  • –Composition is a pipeline, not a graph — no branching or conditionals
Getting started

Four commands to a shareable agent.

See what your machine can actually do

nexus doctor

Scaffold a unit

nexus init my-agent --model llama3.1:8b

A unit is one small YAML file — the model, the system prompt, and the hardware preference order. 

# nexus.yaml
name: research-agent
version: 0.1.0

models:
  - source: ollama:llama3.1:8b   # already on disk? just use it
    context: 8192

entrypoint:
  type: chat
  system_prompt: |
    You are a careful research assistant.

hardware:
  prefer: [npu, gpu, cpu]      # first *usable* one wins

Build and run it

nexus build my-agent && nexus run my-agent:0.1.0 -p "hi"

Point run straight at the directory while you're developing — it skips packaging entirely.

Share it anywhere

nexus push my-agent:0.1.0 ghcr.io/you/my-agent:0.1.0

Or nexus build --seal -o my-agent.nx to carry the whole thing, weights included, to a machine with no network.
